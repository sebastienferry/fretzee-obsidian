# Release preparation

Run the official ESLint recommended configuration with type-aware Obsidian checks. Resolve host integration findings while preserving the shared renderer output and existing block contracts. Keep dynamic presentation in validated CSS custom properties rather than assigning static styles from JavaScript.

Publish a standalone public MIT repository under the authenticated owner. Exclude private vault notes, music files, local paths and generated bundles from source control. GitHub releases provide main.js, manifest.json and styles.css as individual assets plus the complete ZIP. Include dependency notices and original license texts within main.js because the Community installer downloads only the three standard assets.

Use the manifest version as the exact tag. CI builds from the lockfile, runs checks and packages the same release. Record verified desktop compatibility and avoid claiming mobile verification without an actual device test. Keep source and release metadata synchronized. Prepare an English listing and submission checklist; account-policy acceptance remains a final account action.

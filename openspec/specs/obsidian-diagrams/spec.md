# obsidian-diagrams Specification

## Purpose
Provides offline Fretzee diagram and composite sheet rendering, plus selected
Guitar Pro track and measure excerpts in Obsidian notes.

## Requirements

### Requirement: Offline diagram configuration rendering
The plugin SHALL render a single Fretzee diagram from JSON in a fenced `fretzee`
code block through the bundled core renderer without requiring network access.

#### Scenario: Render a Studio configuration
- **WHEN** a note contains a `fretzee` fenced block with a valid raw diagram configuration
- **THEN** the rendered block displays an SVG image generated by the core renderer
- **AND** configured orientation, tuning, fingerings, zones, titles, and colors are preserved
- **AND** the Markdown source remains unchanged

#### Scenario: Render a wrapped diagram record
- **WHEN** a block contains a JSON object with a `config` object
- **THEN** the plugin renders that object's diagram configuration

#### Scenario: Keep normal JSON blocks unchanged
- **WHEN** a note contains a fenced `json` block
- **THEN** the plugin does not register or process that language

### Requirement: Isolated errors and image rendering
The plugin SHALL display errors within the affected block and SHALL display core
SVG without changing the drawing or injecting untrusted markup into the note DOM.

#### Scenario: Invalid configuration
- **WHEN** a block is empty, contains malformed JSON, a non-object configuration, an unsupported sheet, or a renderer-invalid configuration
- **THEN** that block displays a readable text error
- **AND** other diagram blocks remain renderable

#### Scenario: Limit configuration size
- **WHEN** a block exceeds 262,144 UTF-16 code units
- **THEN** the plugin displays a size-limit error before parsing or rendering

#### Scenario: Untrusted labels
- **WHEN** configuration text contains HTML or script-like labels
- **THEN** the plugin displays the generated SVG through an isolated image context
- **AND** labels and error text do not create executable elements in the note DOM

### Requirement: Example insertion and distribution
The plugin SHALL provide an editor command for a valid starter block and a
self-contained Obsidian-compatible installation package.

#### Scenario: Insert a starter diagram
- **WHEN** the user invokes the example insertion command in an editor
- **THEN** a valid fenced configuration is inserted at the current selection
- **AND** a native ephemeral notice reports success or failure

#### Scenario: Install the plugin
- **WHEN** the generated plugin folder is copied into a vault's plugins directory and enabled
- **THEN** Obsidian can load its manifest, CommonJS entry point, and stylesheet
- **AND** the Fretzee renderer is bundled locally

### Requirement: Vault Guitar Pro excerpt selection
The plugin SHALL let users select a Guitar Pro file from the vault, one track,
and an inclusive range of measures and insert an editable `tablature` JSON block.

#### Scenario: Insert a selected excerpt
- **WHEN** the user chooses a Guitar Pro file, track, and valid measure range
- **THEN** the plugin inserts a block with its vault-relative path and one-based selection
- **AND** a native ephemeral notice confirms insertion
- **AND** the source Guitar Pro file remains unchanged

#### Scenario: Cancel the picker
- **WHEN** the user cancels selection
- **THEN** the note remains unchanged

### Requirement: Offline tablature excerpt rendering
The plugin SHALL render the selected track and measures in the note with bundled
AlphaTab and notation fonts without requiring network access or Studio credentials.

#### Scenario: Render selected measures
- **WHEN** a valid `tablature` block references a vault Guitar Pro file
- **THEN** only the selected track and inclusive measures appear in the excerpt
- **AND** Reading view and host-supported Live Preview use the same block processor

#### Scenario: Invalid source or selection
- **WHEN** the file is missing, corrupt, unsupported, oversized, or its track or measure selection is invalid
- **THEN** the affected block displays a readable text error without substituting other content
- **AND** other blocks remain usable

#### Scenario: Referenced file changes
- **WHEN** the referenced Guitar Pro file changes while the block is loaded
- **THEN** the excerpt is refreshed
- **AND** unloaded blocks do not render stale results or retain listeners

### Requirement: Offline composite sheet rendering
The plugin SHALL accept a complete `fretzee_sheet` JSON export in a `fretzee` or
`fretzee_sheet` block and display its diagram items in the configured grid offline.

#### Scenario: Preserve four columns
- **WHEN** an exported sheet has four diagram items and layout.columns is 4
- **THEN** all four diagrams appear in one row in their original order
- **AND** the declared horizontal gap, padding, and sheet title are retained
- **AND** a narrow note scales the diagrams without reducing the column count

#### Scenario: Respect sheet display options
- **WHEN** a supported sheet declares gaps, padding, background, title alignment, visibility, spans, orientation, or uniform-spacing options
- **THEN** these options are reflected in the sheet layout or passed as renderer input
- **AND** each core SVG drawing remains unchanged after rendering

#### Scenario: Ignore cached previews
- **WHEN** sheet items contain thumbnails, identifiers, or duplicate payloads
- **THEN** the plugin renders the actual configuration rather than injecting cached SVG or resolving remote IDs

#### Scenario: Invalid or unsupported sheet
- **WHEN** a sheet is empty, exceeds 64 diagrams or 8 columns, contains invalid layout values, nested sheets, or a non-null palette override
- **THEN** the block displays a readable error without substituting unrelated content

### Requirement: Canonical vault path resolution
The plugin SHALL normalize validated vault-relative Guitar Pro paths with
Obsidian's public normalizePath API before file lookup and event matching.

#### Scenario: Decomposed macOS accents
- **WHEN** a note uses an NFD path and the indexed file has the equivalent NFC spelling
- **THEN** the same vault file is loaded without changing the note or renaming the file

#### Scenario: Canonical source events
- **WHEN** a referenced path and a modify, delete, or rename event differ only in canonical Unicode form
- **THEN** the loaded excerpt refreshes or reports the missing source as appropriate

#### Scenario: Keep path boundaries
- **WHEN** a configuration specifies an absolute path, URL, or traversal segment
- **THEN** the plugin rejects it before canonicalization or file access

### Requirement: Tablature presentation options
The plugin SHALL accept optional zoom, minimal and title fields in JSON or flat key/value tablature blocks while preserving source selection and offline rendering.

#### Scenario: Compact excerpt
- **WHEN** an excerpt specifies zoom 0.7 and minimal true
- **THEN** notation is laid out at 70 percent scale without score metadata, tuning, track labels or chord-diagram headers
- **AND** notes, measures, effects and an explicit block title remain visible

#### Scenario: Compatible defaults
- **WHEN** an existing JSON excerpt omits presentation options
- **THEN** it retains normal scale and full notation headers

#### Scenario: Invalid presentation options
- **WHEN** zoom is nonnumeric, nonfinite or outside 0.25–3, minimal is not boolean, or flat options repeat a key or use unsupported syntax
- **THEN** the block reports a readable local error without accessing the source

### Requirement: Chord progression blocks
The plugin SHALL render a chords fenced block with optional title and key metadata and aligned pipe-delimited measure rows offline.

#### Scenario: Roman numeral and chord rows
- **WHEN** a block contains title and key followed by rows | I / V | IV | and | G / D | C |
- **THEN** both two-measure rows appear in order under their title and key
- **AND** all symbols retain their supplied text without transposition or inference

#### Scenario: Invalid or untrusted progression
- **WHEN** input has inconsistent measure counts, unsupported metadata, excessive size, or HTML-like text
- **THEN** malformed input reports an isolated readable error
- **AND** supplied text never creates executable HTML
